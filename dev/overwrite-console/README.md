# 550C 实时覆写控制台（独立试验页）

影片里那块 `LOCAL SYSTEM DEBUGGER` 的复刻与再创作：**整屏接管**的系统调试器，一边扫描工程资源、一边连上目标路由控制模块、一边把代码冲刷进太空电梯 SEG 07，每完成一个阶段就砸下一块 `REAL-TIME SYSTEM OVERWRITE COMPLETED`，最后落在整座电梯的线框图上，压出中英双语字幕。

**单色 · 白。** 整个动画只有一档颜色，层级全靠亮度和反白来分，不靠色相：最亮 = 正在写入，中亮 = 已确认，暗 = 待处理，极暗 = 未建 / 上一次会话的残留。不做多配色方案。

**这是一个独立网页，还没有接进插件。** `src/`、`lib/`、`package.json` 一行未改。

```
dev/overwrite-console/
├── index.html      ← 全部内容（自包含：内联 CSS + JS，无外链、无构建）
├── shoot.mjs       ← 抓帧 / 实时播放 / 整条时间线自检
├── check.mjs       ← 自包含体检（外部引用数、CSS 块里的反引号数）
├── probe-band.py   ← 像素级探针：把可疑横带的原始数据打出来
└── shots/          ← 抓帧输出（已 gitignore）
```

## 怎么看

直接双击 `index.html` 就行，不需要起服务、不需要构建。

| 操作 | 作用 |
|---|---|
| `空格` | 重播 |
| `P` | 暂停 / 继续 |
| `D` | 调试读数（`t`、阶段、进度、面板实际矩形、该点最上层的元素） |
| 点击画面 | 重播 |

查询串：`?at=5200` 定格在第 5.2 秒 · `?still=1` 冻结 CSS 动画 · `?w=1440&h=860` 钉死舞台尺寸 · `?speed=0.5` 半速 · `?loop=1` 循环 · `?debug=1` 显示调试读数 · `?sweep=1` 跑整条时间线自检。

```powershell
node dev/overwrite-console/shoot.mjs --times 2600,5200,10800,12400   # 抓关键帧
node dev/overwrite-console/shoot.mjs --sweep                          # 整条时间线自检
node dev/overwrite-console/shoot.mjs --live --times 5000,13400        # 实时播放路径
node dev/overwrite-console/check.mjs                                  # 自包含体检
python dev/overwrite-console/probe-band.py shots/t12400.png           # 像素级探针
```

## 太空电梯：组装 → 上升，两段

第一版只做了"塔一节一节长出来"，那读起来是**建造**，不是**电梯在上升**。太空电梯的上升镜头是另一回事，现在分两段：

**组装段（1.3s → 6.6s）**——把结构写出来（"加载"）：

| 特征 | 做法 |
|---|---|
| 轨道而非桅杆 | 中央两条平行导轨＋横档（爬升舱骑的那条"天梯铁路"），外面才是围着它**收分**的四柱桁架 |
| 庞大基座站 | 六边形平台＋底裙＋撑到地面的支柱＋六个着陆坪＋两圈呼吸灯环 |
| 大气分层 | 低空三道云带、地平线雾霭、往上过渡到星空 |
| 逐节写入 | 幽灵轮廓先铺满，塔身一节节被点亮，锁扣闪一下并向外扩一圈冲击环；镜头随塔长高从 5.4 km 拉到 14 km 可见高度 |

**上升段（7.6s → 10.8s）**——轿厢沿缆索射上去，这是整支动画的收束：

| 做法 | 效果 |
|---|---|
| 可见高度 **14 km → 560 km**（前段拉得快、后段慢） | 起升那一刻"地面在往下掉"，随后看得清地球的弧 |
| 轿厢标高 **0.9 km → 420 km**（`pow(k,1.45)` 加速） | 有推力感，不是匀速漂 |
| 地平线用真实曲率 `d²/(2R)`（R = 6371 km） | 同一套画法从"一片平地"变成"一颗行星的边" |
| 地球边线加亮加厚 ＋ 贴着它的大气辉光带 | 从太空回看地球的标志，也是画面下半部唯一的填充物 |
| 雾霭随高度淡掉、星空提亮 | 从大气层穿到真空 |
| 比例拉大后舱体不足 4px → 改画**亮点＋辉光＋尾迹** | 该简化就简化，而不是硬画一个看不见的盒子 |
| 结构自下而上的**速度拖影** ＋ 横贯画面的**高度标线** | 上升的体感八成来自这两层 |
| 缆索改成**三条线组成的带**，并始终高过轿厢 | 比例拉远后它是画面上唯一贯穿上下的元素，得撑得住 |
| 基座站留一点**余辉** | 缩成一个点时，"我从哪来"仍然看得见 |

标尺刻度随比例换档（`1/2/5/10/20/50/100/200/500/1000`），因为可见高度跨了 100 倍，写死 2 km 就不对了。

## 动画是怎么"动"起来的

第一版每块面板都在闪、每样东西都在出现，但整体读起来像幻灯片。这一轮把"运动"补在五条平行线上——任何时刻至少两条在跑：

| 层 | 做法 |
|---|---|
| **整屏** | 极慢纵向滚动漂移 + 拍点上的 33ms 粒度横向错位 + 亮度呼吸（横幅落点、塔身锁节都会抬一下） |
| **面板** | 成形是 `clip-path` 从左到右的擦除，写入边缘留一条亮线；七个面板错开 105ms |
| **资源树** | 整棵树先以极暗行铺满，扫描前沿逐行点亮，一条亮线跟着前沿连续下移，刚扫过的行闪一下 |
| **代码墙** | 窗口取 `floor` 之后把小数部分做成 `translateY`——连续流动，而不是一次跳一整行 |
| **太空电梯** | 全程慢速环视；塔身逐节写入（四条边依次画出、斜撑后补）、锁扣闪光并向外扩冲击环、地面脉冲环一圈圈扩散、爬升舱带尾焰和信标 |
| **横幅** | 过冲 4% 回弹 + 落点反白闪两次 + 一条从中心向两侧扫出的冲击波横线 |

## 太空电梯：三层做法

这是这段动画的难度所在，也是它区别于"静态线稿"的地方：

- **幽灵轮廓**——整座电梯的完整线框一开始就以 0.22 透明度铺在画面上（CAD 里等待建造的模型），观众当场就知道"要长出什么"
- **逐节写入**——每 290ms 一节塔身被写进轮廓：横边依次画出、斜撑后补、锁扣闪一下、左侧刻度亮一格、日志落一行；共 24 节
- **镜头拉远**——塔越高投影比例越小（`S = min(w/8.6, h*0.76/span)`），画面自动退到刚好装下整座电梯的位置，地面网格始终张开

结构含：基座六边形平台 + 六个着陆台、四柱桁架 + X 斜撑（只画朝向相机的两面）、双导轨、三部爬升舱 + 载荷吊舱、配重、轨道环 + 虚线轨道平面、地面网格、高度标尺、技术图纸式引线标注（会互相顶开）。全部是 3D 线框投影到 canvas 的纯描边，亮线走两遍（粗而淡的辉光 + 细而实的本体）。

## 接进插件的路径（还没做）

1. `index.html` 的 `<style>` 里 `:root` 那组令牌直接搬进 `src/enhance.js` 的 `ENHANCE_CSS`（注意那个文件里的告示：**CSS 块里绝不能出现反引号**——`check.mjs` 会替你确认这一条）；
2. `<script>` 主体搬成 `src/show.js` 里的一个 `phaseOverwriteConsole()`，把内部的 `t` 换成由 show 时钟驱动（`render(t)` 不用改），rAF + interval 双驱动换成 `later()`/`sleep()` 那条可取消的链路，并且要能被 `cancel()` 同时拆掉；
3. `?at=` / `still` / `w` / `h` / `sweep` 这几个自检入口保留——它们是唯一能在无头环境里逐帧验证这段动画的手段；
4. 设置项加一个 `dsh-550c-boot:overwrite`（`classic` / `console`），默认 `classic`。即"旧覆写 / 新实时调试器"二选一，不替换。

## 踩过的坑（都写进代码注释了）

| 现象 | 真因 |
|---|---|
| 电梯面板"设了尺寸却看不见" | **绝对定位的网格子元素若带确定的 `grid-area`，规范规定它以那个网格区域作为包含块**——`left/top` 于是相对格子而不是工作台，面板被推到 `(914,511)` 屏幕外。解法：`.hero` 上加 `grid-area:auto` |
| 无头截图里"页面自量尺寸"和画面不符 | 带 `--screenshot` 时浏览器先用默认视口（约 750×485）布局并跑完脚本，直到截图前才套用 `--window-size`，那时 JS 已冻结、`resize` 不派发。解法：`?w=&h=` 钉死舞台尺寸 |
| 改了代码却抓出字节完全相同的一帧 | Chromium 对 `file://` 的缓存以路径为键、会忽略查询串。解法：抓帧脚本自起 `no-store` 本地服务 + 时间戳查询串 |
| 抓帧脚本整体挂死 | 服务跑在同进程里却用了 `spawnSync`，事件循环被阻塞，浏览器永远等不到响应。解法：改异步 `spawn` |
| 动画一开场就是 97% | 进度写成"各里程碑各算一次再 `Math.max`"，而 `lerp(from,to,0)` 恒等于 `from`——最后一段的 97 从 `t=0` 就成了地板。解法：显式分段表 |
| 无头环境实时播放抓到全黑 | `requestAnimationFrame` 没被虚拟时间驱动。解法：rAF + `setInterval` 双驱动同一个 `advance()`（真实浏览器里后台标签页 rAF 被节流时也更稳） |
| 横幅旁边永远横着一条亮带 | 扫光元素跑完一次后停在 `translateX(-100%)`，而它没有透明度控制。解法：扫光 / 冲击波 / 故障条全部由 JS 收尾，空闲时连 `visibility` 一起关掉 |
| 片尾有一条横贯整屏的虚线带 | **它本来就是设计里的故障条**（`commitAt-400` 那个拍点），只是 8px 高、整屏宽，读起来像渲染坏了。解法：改成局部、2px、更细的撕裂段。教训：先确认那是设计还是 bug 再动手——我在它身上花了相当久才想到去数像素 |

## 验证

- `--sweep`：整条时间线逐 50ms 渲染一帧（285 帧 × 10 个渲染步骤），查异常，并检查进度 / 已扫描行数 / 已落下横幅 / 已锁定节数**只增不减**，两种尺寸下均为 0 问题
- `--live`：同时间点的实时播放帧与定格帧基本一致（如 5000ms：378 KB vs 364 KB），说明不是"只有截图好看"
- `check.mjs`：0 处外部引用、CSS 块里 0 个反引号
- `probe-band.py`：像素级确认故障条只占 x 677..1403
